  ARCHITECTURE DETECTED BEFORE PHASE 3
  -----------------------------------
  O projeto já tinha uma decomposição parcial em MVC com Service Layer, mas
  ainda possuía regras críticas fora das camadas: autenticação não reutilizável,
  rotas operacionais sem autorização, commits dentro de Models, validação ad hoc
  e health/reset acoplados à persistência.

  app.py (entrypoint)
      -> src.app.create_app() (composition root)
          -> src.views.routes (registro HTTP)
              -> src.controllers (adaptação request/response)
                  -> src.services (regras de negócio)
                      -> src.models (persistência e mappers)
                          -> src.db.database / Flask g / SQLite

  FINAL ARCHITECTURE AFTER PHASE 3
  --------------------------------
  View (rotas) -> Controller (HTTP) -> Schema (DTO) -> Service (caso de uso)
  -> Model (SQL parametrizado) -> Database (conexão por request) -> SQLite.
  `src/domain/pedido.py` concentra estados e transições; `src/middlewares/`
  concentra autenticação, autorização e erros transversais; `src/config/`
  concentra ambiente, versão, CORS e credenciais de seed opcionais.

  LAYER MAP
  ---------
  - View: `src/views/routes.py` registra URLs e encaminha para controllers.
  - Controller: `src/controllers/` adapta request, autorização e resposta JSON.
  - Schema: `src/schemas/payloads.py` valida e tipa entradas da aplicação.
  - Service: `src/services/` executa regras, transações, auth e efeitos laterais.
  - Domain: `src/domain/pedido.py` define a política de status do pedido.
  - Model: `src/models/` executa SQL parametrizado e mapeia linhas.
  - Database: `src/db/database.py` gerencia DDL, seed, migração e lifecycle de `g`.
  - Middleware: `src/middlewares/` trata auth e erros HTTP de forma transversal.

  SECURITY AND PERFORMANCE BASELINE
  ----------------------------------
  - Secret key ausente gera valor aleatório em desenvolvimento e falha em produção.
  - Tokens Bearer são assinados, expiram e recarregam o papel atual no banco.
  - Senhas de seed são opcionais, vêm do ambiente e são hasheadas antes do INSERT.
  - Criação de pedidos usa `BEGIN IMMEDIATE`, atualização condicional de estoque,
    agregação de itens duplicados e rollback em qualquer falha.
  - Pedidos carregam seus itens em lote com `LEFT JOIN`, sem N+1.
  - CORS só é habilitado para as origens explicitamente configuradas.
