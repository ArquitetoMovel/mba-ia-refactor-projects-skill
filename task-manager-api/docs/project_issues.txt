[CRITICAL] Weak hardcoded fallback SECRET_KEY — token forgery
  file: config/settings.py               line: 8
  symbol: Settings.SECRET_KEY
  description: SECRET_KEY cai no default publico 'change-me-in-production'
  quando a env nao esta definida; .env versionado no deploy repete o mesmo
  valor. Como AuthController assina tokens com esse segredo, um atacante que
  conheca o default (esta no codigo-fonte e no .env.example) forja tokens de
  qualquer user_id — comprovado em runtime: URLSafeTimedSerializer com a chave
  default desserializa token forjado com sucesso. Falha de release blocker.

[HIGH] Missing transaction boundaries — no rollback on commit failures
  file: controllers/user_controller.py   line: 36-37, 61, 70-72
  file: controllers/task_controller.py   line: 60-61, 94, 103-104
  file: controllers/category_controller.py line: 23-24, 40, 50
  file: middlewares/error_handler.py     line: 32-35
  symbol: *.commit(); handle_integrity_error
  description: Todo fluxo de escrita usa db.session.commit() avulso, sem
  try/except com db.session.rollback(). Um IntegrityError/OperationalError no
  commit deixa a sessão suja e contamina pedidos subsequentes do mesmo worker
  até restart. O handler de IntegrityError responde 409 mas nunca faz rollback,
  e delete_user (linhas 70-72) executa 2 operações multi-tabela sem limite
  transacional atomico declarado.
